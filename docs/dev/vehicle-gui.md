# Vehicle GUI

The vehicle GUI changes vehicle parameters. It can also swap components. It always saves new files. It does not change the original files. It checks the result with the real compiler before it writes anything.

## Install

Install the GUI extra from the repository root:

```bash
python -m pip install -e '.[gui]'
```

## Start the GUI

Start the application from the repository root. The optional argument is a vehicle-formulation file:

```bash
PYTHONPATH=src:. python3 tools/vehicle_gui/app.py
PYTHONPATH=src:. python3 tools/vehicle_gui/app.py models/formulations/iem24_murphy_real_planar_7dof.xml
```

## Open a vehicle

Select **Open…** and choose a `vehicle-formulation` file. Bare `vehicle-assembly` files are rejected. They do not identify a formulation subtype. The left tree shows one row for each slot at any depth. An example is `powertrain/power-plant`. The tree uses the same slots as the simulation GUI. The third column marks a slot as `edited` or `swapped`.

## Edit parameters

Select a slot. The table lists the parameters of its file. Double-click a **Value** cell and type a number. The unit column cannot be edited. A value that is not a finite number is refused with a message in the status bar. If you type the value that the file already has, the edit is removed.

The text of the file is changed in place. The comments, the spacing and the order of the lines stay as they are. The **File value** column keeps the original value.

The panel **Checks (the real compiler)** compiles the changed vehicle after each edit. It shows the verdict. It also shows parameters that no model consumes. It shows roles that no component uses. A value that the compiler rejects turns the verdict red. For example, `unit_count` must be a whole number. A save of such a vehicle writes no file. It shows the reason.

## Swap a component

Select a slot. The list shows the registered components that fit the slot. The rule is the one of the simulation GUI. Select a component and **Use this component**. **Revert slot** removes parameter edits for that slot. It does not restore a previous component choice.

## Generated slots are locked

Some component files carry the comment `Generated by tools/...` (suspension layouts, springs, anti-roll bars, kinematics, dampers and hydraulics). Their values come from a generator. The GUI shows them as read-only and names the tool. You can still swap such a slot for another component. To change a value, change the input of the generator and run it again.

## Save

The save bar has a folder, a file name and two switches. The default folder is `vehicles_out/` in the repository root. Git ignores it. A save replaces all files for the chosen stem. It removes stale `<stem>__*.xml` outputs from earlier saves in the same folder. It stages and validates the complete set first. A normal in-process replacement failure restores the prior set. If rollback itself fails, cleanup continues. The original error remains raised. The staging and backup directory is retained with a recovery-path note. An affected target may be missing until recovery. Abrupt termination or power loss during commit is outside the guarantee.

**Save as new vehicle** writes these files:

| File | Content |
|---|---|
| `<name>__formulation.xml` | The formulation. Open this file in the simulation GUI. |
| `<name>__vehicle.xml` | The assembly. This file is always written. |
| `<name>__<slot>.xml` | One file for each edited slot and for each parent of an edited or swapped slot. A slot path uses `__` for `/`. |

Files that did not change are referenced and not copied. Each copied model gets the id suffix `.<name>`. Each copy has a line `Saved by tools/vehicle_gui from <original>` after the XML declaration. A copy of a generated file does not claim to be generated. Its `Generated by` comment becomes `Derived from output of`.

**Save this slot as a new component…** asks for a model id. The save bar's file name sets the output stem. The component is written as `<file-name>.xml`. The model id is stored inside that file. A generated slot cannot be saved with changed values.

The GUI applies these rules:

- Open accepts a `vehicle-formulation` only. A bare `vehicle-assembly` is rejected because its formulation subtype is unknown.

- A folder inside `models/` is refused unless you tick **Allow writing inside models/**. The `models/sweeps/` folder is exempt.
- An existing file is refused unless you tick **Overwrite existing files**.
- If the compiler rejects the vehicle, the GUI writes no file.
- The file name has 1 to 40 letters, numbers, `_` or `-`.

## Limits

- The GUI edits `<parameter>` values only. It does not edit LUT or NPZ data. Use the generators, for example `tools/model_data/generate_component_sweep.py`.
- The GUI does not create a component from nothing and does not import a spec sheet. Use `tools/data/import_vehicle_spec_sheet.py` for that.
- Windows and Linux are not tested. Only macOS was used.
