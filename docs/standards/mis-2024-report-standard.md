# MIS 2024 report standard

This is the required format for any **MIS 2024 report** produced in this
repository: a document that compares a simulated lap of the 2024 Michigan
endurance circuit against measured or reference data, or that reports a
simulated MIS 2024 lap in a way intended to be read as a validation result.

If the user asks for "an MIS 2024 report", "an MIS endurance report", or an
"IEM24 Murphy report", the result must follow this document. The reference
implementation is [the IEM24 Murphy stint report](../validation/iem24-murphy/report.md),
generated by `tools/compare_iem24_murphy_stint.py`.

## When this standard applies

| Applies | Does not apply |
|---|---|
| A simulated-vs-measured MIS 2024 lap comparison | A single scalar answer ("what is the lap time?") |
| An updated IEM24 Murphy report | A parameter sheet or a component model document |
| Any new MIS 2024 stint or lap validation | Internal experiment logs under `.superpowers/` |
| A MIS 2024 result quoted as a validation claim | Exploratory notes that are explicitly marked as provisional |

A report that intentionally departs from this standard must say so in its
first paragraph and give the reason.

## Required structure

Every section below is required, in this order, with these heading levels.
Subsections may be added inside `Measured data` and `Trace comparison`.

| # | Section | Must contain |
|---|---|---|
| 1 | `# <Title>` | The circuit, the car, and whether the result is simulated vs measured |
| 2 | `## Configuration` | Bullet list of every model value that a reader needs to reproduce the lap: mass and its breakdown, aero, chassis, drivetrain, control limits, and initial conditions |
| 3 | `## Measured data` | Source file and window, the lap table, how measured and simulated laps were put on one axis, and every correction applied to the raw channels |
| 4 | `## Trace comparison` | The metric table, then every comparison figure embedded inline |
| 5 | `## Reading the comparison` | Quantitative, per-channel interpretation; the lap-time gap and its cause |
| 6 | `## Caveats` | Values carried over rather than measured, unresolved offsets, and known model limits |
| 7 | `## Reproduce` | Copy-pasteable commands that regenerate the report from scratch, and the name of the generating tool |

A report is incomplete if any required section is missing. Do not merge
`Caveats` into `Reading the comparison`, and do not omit `Reproduce` on the
grounds that a sibling document already has it: the report must stand alone.

## Required tables

### Lap table, in `Measured data`

One row per measured lap, with the standing-start lap included and flagged, and
flying laps used for all statistics.

| Column | Unit | Notes |
|---|---|---|
| Lap index | – | Stable identifier used by the metric tables |
| Start time | s | Log clock at the lap boundary |
| Lap time | s | State whether the lap is a standing start or flying |
| Driven distance | m | Integrated from the measured speed |
| Mean speed | m/s | Driven distance ÷ lap time |
| Closure radius | m | Quality control for the segmentation |

State the median flying-lap time and distance in prose next to the table, and
the percentage by which the driven line differs from the modelled centreline.

### Metric table, in `Trace comparison`

One row per compared channel, in the same order as the figure panels.

| Column | Definition |
|---|---|
| RMSE | Root-mean-square of (simulated − measured) |
| MAE | Mean absolute error |
| `Bias (sim − meas)` | Mean of (simulated − measured), signed |
| Correlation | Pearson correlation over the comparison grid |
| Normalised RMSE | RMSE ÷ standard deviation of the measured trace |

Report the bias with an explicit sign convention: `sim − meas`.

## Required figures

Every figure is embedded inline with a Markdown image link to a file in the same
directory. A figure that exists on disk but is not embedded is a defect; a
figure that is linked but missing is a defect.

| File | Content |
|---|---|
| `comparison.png` | One panel per compared channel, sharing a distance axis. Each panel shows the measured lap range as a band, the measured median lap, and the simulation. |
| `lap_spread.png` | Lap-to-lap consistency (every measured lap, the median, and the simulation) plus a distribution panel for a second signal |
| `simulated_lap.png` | The raw simulated lap on its own, including the initial-condition channel |

Alt text states what the figure shows, not the filename. Keep the figure order
consistent with the metric table so a reader can move between them.

## Comparison channels

A MIS 2024 report compares these channels unless the request narrows the scope.
Adding a channel is allowed; silently dropping one is not.

| Channel | Unit | Source |
|---|---|---|
| Speed | m/s | Body-frame velocity magnitude |
| Longitudinal acceleration | m/s² | Body-frame longitudinal accelerometer |
| Lateral acceleration | m/s² | Body-frame lateral accelerometer |
| Yaw rate | rad/s | Vertical gyro |
| Motor torque request | N·m | Per-motor commanded torque |
| Pack terminal voltage | V | `VPack` |

## Conventions

These conventions are not preferences; they are what makes two reports
comparable.

- **Units.** SI throughout, with the unit in every axis label and table header.
  Do not mix kgf, bar, or rpm into the comparison tables.
- **Body frame.** SAE vehicle axes: `x` forward, `y` right, `z` down. Positive
  yaw rate is a right turn and positive lateral acceleration moves load to the
  left wheels.
- **Sign conventions.** Report bias as `sim − meas`. Report brake pedal force
  and hydraulic pressure as positive magnitudes. Report regenerative torque as
  negative when the model distinguishes it.
- **Mass.** Total mass is the car plus the driver, with both values stated. If a
  stint has a known driver mass, use it and say so.
- **Geometry.** State the reference for `CGx` (which axle it is measured from)
  and how it maps onto the model's parameter.
- **Filtering.** Measured channels are low-pass filtered before comparison
  because the simulated lap is quasi-static. State the cutoff and the filter
  order, and apply the same filter to the simulated trace. Prefer a zero-phase
  filter whose step response does not overshoot a physical limit.
- **Statistics.** Use the median across flying laps for the measured reference
  trace, and report the per-lap spread. Exclude the standing-start lap from
  all flying-lap statistics, but keep it in the lap table.
- **Lap axis.** Put measured and simulated traces on one physical lap-distance
  axis. An inferred phase offset is acceptable only when no geometry exists;
  say so explicitly and show the alignment objective.
- **Channels taken from a log.** State the source file, its SHA-256 when
  available, the sample rate, and the exact channel names consumed.

## Mandatory disclosures

A report is not finished until each of these appears somewhere in it.

1. **Provenance.** The measured source file, its hash or size, the sample rate,
   and the time window actually used.
2. **Carried-over values.** Every model value that was *not* measured for this
   car, listed by name. "These are the values we did not measure" is a required
   sentence, not an optional one.
3. **Initial conditions taken from data.** Every state initialised from the log
   (state of charge, pack voltage, tire state, ambient) and the value used.
4. **Residual offsets.** Any channel whose error is dominated by a known
   initial-condition or convention difference rather than by model structure.
   Separate these from genuine model error in the text.
5. **Corrections applied.** Any rotation, unit conversion, or re-derivation
   applied to the raw channels, with the measured effect.
6. **Solver status.** Convergence state, iteration counts, and whether the
   reported lap is an optimum or a feasible point.

## Writing rules

- Lead each finding with the number, then the interpretation. "The simulation
  is 5.88 s slower (77.56 s against 71.69 s)" beats "the simulation is slower".
- Never present a trace-comparison number without saying which lap or set of
  laps it refers to.
- When a comparison is unfavourable, say so plainly and identify whether the
  cause is the model, the initial condition, or the alignment.
- Do not claim a result is validated. State what agrees, to what tolerance, and
  over what window.
- Figures use the repo palette: measured median `#1f4e79`, measured band
  `#9dc3e6`, simulation `#c00000`.
- Keep the report self-contained: a reader with only this file must be able to
  find the data, the code, and the caveats.

## Checklist before delivery

- [ ] All seven required sections present, in order.
- [ ] Lap table lists every lap, standing start flagged.
- [ ] Metric table has one row per compared channel with all five statistics.
- [ ] Every figure embedded inline, and every embedded figure exists on disk.
- [ ] Units and the `sim − meas` sign convention stated.
- [ ] Filter cutoff, filter order, and the lap statistic (median of flying laps) stated.
- [ ] Measured path and simulated lap share one physical distance axis.
- [ ] All six mandatory disclosures present.
- [ ] `Reproduce` commands run end to end from a clean checkout.
- [ ] Re-running the generator reproduces the file byte for byte.
- [ ] The full test suite passes and `git diff --check` is clean.

a finding to report, not a section to remove.
