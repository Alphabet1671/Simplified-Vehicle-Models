# XML-Declared Motor LUT Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and integrate a deterministic motor LUT that performs forward power evaluation and inverse bus-power-to-torque lookup, with analytical out-of-domain fallback and measured end-to-end speedup.

**Architecture:** Extend the XML model with explicit external data declarations, generate a normalized-load NPZ table from the current analytical motor model, and compile it into immutable runtime arrays. The powertrain assembly will query the table directly for motoring and regen limits, while the analytical functions remain available only for out-of-domain fallback and validation.

**Tech Stack:** Python 3.12, NumPy, `dataclasses`, XML `ElementTree`, `unittest`, compressed NPZ data.

**Spec:** `docs/superpowers/specs/2026-10-12-motor-lut.md`

## Global Constraints

- Backward compatibility for electric-motor XML without a LUT is not required.
- The analytical evaluator must remain as an out-of-domain fallback.
- Signed shaft torque, motor rpm, and bus voltage are the public lookup coordinates.
- Efficiency is derived from shaft and bus power; it is not a persisted interpolation field.
- Default exact drive-cache behavior must remain unchanged.
- Do not merge or push without user approval.

- [ ] **Step 3: Implement a specialized interpolator**

Use scalar index arithmetic and hand-unrolled trilinear weights rather than allocating NumPy arrays per query. First bilinearly interpolate directional torque limits over voltage/speed, convert torque to normalized signed load, then interpolate `bus_power` and `loss_power`. Compute shaft power analytically and derive inverter-inclusive efficiency with the existing directional convention.

When voltage, speed, or normalized load is outside the persisted domain, call `evaluate_shaft_power_exact`; do not clamp or extrapolate.

- [ ] **Step 4: Implement direct inverse lookup**

For the requested direction, bilinearly interpolate bus-power values over voltage/speed for each directional load node, locate the target with `searchsorted`, and linearly invert adjacent load values. Convert load to torque with the interpolated envelope, perform one forward LUT evaluation, and report its residual. If the target, voltage, or speed is outside the table, use a bracketed analytical fallback and set `used_fallback=True`.
