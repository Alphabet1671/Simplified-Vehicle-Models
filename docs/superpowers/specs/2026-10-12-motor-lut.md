# XML-declared motor LUT specification

## Goal

Replace repeated runtime motor current/loss solves with a precompiled, XML-declared motor operating table and direct inverse torque-for-bus-power queries, while retaining the analytical evaluator only as an explicit out-of-domain fallback. Measure end-to-end solver time and numerical displacement against the current exact model.

## Decisions

- Backward compatibility is not required. The canonical electric-motor XML must declare its LUT data.
- The public operating coordinates are bus voltage, motor speed in rpm, and signed shaft torque.
- Shaft power and efficiency are derived values, not independent axes.
- The persisted table uses a normalized signed load coordinate bounded by separately compiled motoring and regenerative torque envelopes. This avoids interpolation across feasible/infeasible rectangular cells.
- Persist bus power and motor loss power. Derive efficiency from shaft and bus power.
- Provide a direct inverse query from target bus power to torque. Drive inversion may use monotone lookup. Regen inversion must scan every piecewise-linear negative-load segment because analytical regen bus power is genuinely non-monotone, and choose the most-negative (maximum braking magnitude) torque satisfying the charge-power constraint. Drive and regen assembly paths use this query rather than iterative motor-loss or torque bisection solves.
- Retain the analytical evaluator and current source maps inside the compiled parameters for queries outside the LUT voltage, speed, or load domain. Do not silently extrapolate.
- LUT generation is deterministic and records source digests, axes, units, and generator version.
- Keep the default exact drive-cache policy unchanged. Following the corrected baseline, envelope fixes and regulatory voltage clamp, all numerical/performance gates pass and the user approved promotion: `PowertrainParameters.motor_mode` defaults to `"lut"`. `"analytical"` remains an explicit reference mode; out-of-domain LUT queries still use the exact analytical fallback.

## Required interfaces

- XML data declaration separate from model-to-model `ref` references.
- `evaluate_motor(parameters, motor_speed_rpm, shaft_torque, bus_voltage) -> ShaftPowerResult`.
- `motor_torque_limits(parameters, motor_speed_rpm, bus_voltage) -> TorqueLimits`.
- `torque_for_bus_power(parameters, motor_speed_rpm, bus_voltage, target_bus_power, direction) -> TorqueSolveResult`.
- Existing assembly result types remain stable unless a test demonstrates that a field is no longer meaningful.

## Numerical requirements

- Validate all persisted axes as finite and strictly increasing.
- Validate map shapes, finite output values, nonnegative loss, directional signs, productive-regen mask correctness, and monotone drive bus power. Do not impose monotonic bus power on regen rows or truncate their complete feasible negative-torque envelopes; any contiguity check must reflect physical feasibility rather than assume productivity is a monotone prefix.
- The out-of-domain fallback must be observable through diagnostics or tests.
- Compare forward operating points over deterministic random and boundary samples.
- Compare drive and regen force limits over representative speed/SOC points.
- Compare an exact assembled MIS flying lap. Report lap-time displacement, speed-trace displacement, force residual/constraint behavior, table load/build cost, solver wall time, lookup count, inverse-query count, and fallback count.
- Run the complete test suite before concluding.

## Benchmark gates

The implementation is acceptable for experimental use when:

- the exact assembled MIS lap converges;
- lap-time displacement is no greater than 1 ms;
- maximum speed-trace displacement is no greater than 0.05 m/s;
- no drive, regen, voltage, speed, or tire constraint is violated beyond existing test tolerances;
- the LUT lap is measurably faster than the analytical baseline on repeated same-process runs.

If any gate fails, keep the implementation and benchmark evidence isolated in its feature commit(s), document the failure, and do not claim a default performance win.
